# Makano

Каталог коворкингов и свободных помещений Северного Кавказа. Старт — Грозный.
Статический сайт: без бэкенда, без Cloudflare, без Stripe. Хостинг — GitHub Pages,
домен — `makanospace.com`.

Спецификация продукта: [`docs/product/coworking-network-spec.md`](../../docs/product/coworking-network-spec.md)

## Как устроено

```
data/site.json      — бренд, домен, контактный телефон, endpoint форм
data/spaces.json    — все площадки каталога (единственный источник данных)
src/styles.css      — стили
src/app.js          — фильтры каталога + отправка заявок
build.js            — генератор статики (Node, без зависимостей)
dist/               — результат сборки (в git не хранится)
```

## Сборка и просмотр

```bash
node build.js                 # собрать сайт в dist/
cd dist && python3 -m http.server 8765   # открыть http://localhost:8765
```

Зависимостей нет — нужен только Node.

## Как добавить площадку

Добавьте объект в `data/spaces.json` и пересоберите. Поля:

| Поле | Значение |
|------|----------|
| `id` | латиницей, попадает в URL: `/space/<id>/` |
| `type` | `coworking` или `partner_space` (партнёрское помещение) |
| `format` | `mixed` или `women_only` |
| `amenities` | `wifi`, `meeting_room`, `printer`, `kitchen`, `parking`, `coffee`, `silence_zone`, `whiteboard` |
| `pricePerHour` | число или `null`; `priceNote` — текстом, если цена нестандартная |
| `verified` | `false` → на странице показывается предупреждение, что данные не подтверждены |

Новые города и удобства появляются в фильтрах автоматически.

## Что нужно сделать перед публичным запуском

1. **Подтвердить данные площадок.** Все три карточки собраны из открытых источников
   (2ГИС/Яндекс.Карты), `verified: false`. После звонка — проставить цены, часы и `verified: true`.
2. **Зарегистрировать домен** `makanospace.com` и направить DNS на GitHub Pages.
3. **Наполнить каталог** партнёрскими площадками (языковые центры, студии) — минимум 5-10,
   иначе каталог выглядит пустым.
4. **Опционально: подключить Formspree.** Пока `formspreeEndpoint` пустой, заявки уходят
   в WhatsApp готовым сообщением — этого достаточно для старта.

Контактный телефон настроен: `+7 938 004-65-31` (`data/site.json`). На него приходят все заявки.

⚠️ Поле `telegram` в `data/site.json` сейчас содержит заглушку `makano_bot` — такого аккаунта
может не существовать. Замените на реальный юзернейм бота или личного аккаунта (без `@`),
иначе в подсказке под кнопкой будет указан несуществующий чат.

## Как работают заявки без бэкенда

- `formspreeEndpoint` пустой → в форме две кнопки, канал выбирает сам отправитель:
  - **WhatsApp** — открывается чат с номером из `contactPhone` и готовым текстом заявки;
  - **Telegram** — открывается диалог выбора чата с тем же текстом; кнопка появляется,
    только если заполнено поле `telegram` (юзернейм без `@`).
  В обоих случаях человек дожимает «отправить» сам — сайт ничего не отправляет за него.
- `formspreeEndpoint` заполнен → показывается одна кнопка, заявка уходит POST-запросом
  на Formspree, мессенджеры не открываются.

**Почему не бот с токеном.** Токен Telegram-бота пришлось бы положить в JavaScript
публичного репозитория — любой смог бы слать сообщения от имени бота. Автоматическая
доставка в бота требует кода на сервере, которого у статического сайта нет.

## Деплой

`.github/workflows/deploy.yml` собирает сайт и публикует на GitHub Pages при пуше в `main`.
Он сработает, когда проект переедет в собственный репозиторий (внутри `Auto-Company`
вложенные workflow не запускаются). Файл `CNAME` для домена генерируется сборкой автоматически.
